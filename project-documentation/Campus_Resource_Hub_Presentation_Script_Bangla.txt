SLIDE 07 — EVERY RESOURCE IS CHECKED BEFORE PUBLICATION
সময়: প্রায় ৭০–৮০ সেকেন্ড
------------------------------------------------------------
Speaker Script:

Authenticated user PDF, DOCX, PPTX, XLSX অথবা image upload করতে পারে এবং
title, course, department ও semester metadata দেয়। Backend প্রথমে file-এর
available text এবং visual sample extract করে।

Safety pipeline-এর প্রথম ধাপ একটি local deterministic keyword filter, যা
obvious unsafe text zero API cost-এ ধরতে পারে। এরপর AI moderation-এর primary
provider হলো Groq। Text moderation-এর জন্য primary safeguard model
“openai/gpt-oss-safeguard-20b”, এবং image বা visual inspection-এর জন্য
configured model “qwen/qwen3.6-27b”।

Groq unavailable হলে configured fallback হিসেবে Hugging Face-এর
“zai-org/GLM-4.5V” চেষ্টা করা হয়; final optional moderation fallback হলো
OpenAI “omni-moderation-latest”।

Content fully checked এবং clean হলে publish ও index হয়। Harmful, partially
inspected অথবা provider-unavailable file public না করে human review queue-তে
রাখা হয়। Moderator approve করলে publish হয়; reject করলে uploader notification
পায়।

এই fail-safe design-এর মূল কথা হলো—AI service fail করলেও content কখনো
silently safe ধরে automatic publish করা হয় না।

Transition:
Resource-এর পাশাপাশি campus update কীভাবে structured রাখা হয়েছে, এখন সেই
module-গুলো দেখি।

SLIDE 11 — SEARCH BY MEANING, NOT JUST KEYWORDS
সময়: প্রায় ৭৫–৮৫ সেকেন্ড
------------------------------------------------------------
Speaker Script:

Traditional keyword search-এ query এবং stored title-এর exact word না মিললে
relevant content miss হতে পারে। CRH meaning-based semantic search ব্যবহার করে।

Exact embedding model হলো local quantized
“Xenova/paraphrase-multilingual-MiniLM-L12-v2”। এটি Bangla ও English text-কে
384-dimensional vector-এ convert করে। Resource title ও metadata-এর পাশাপাশি
PDF বা Office file-এর extracted passage ResourceChunk হিসেবে index করা হয়।

User প্রশ্ন করলে query embedding তৈরি হয় এবং MongoDB Atlas Vector Search
relevant content rank করে। Atlas unavailable হলে in-memory cosine similarity,
তারপর regex search fallback আছে।

Retrieved content ব্যবহার করে RAG assistant numbered ও clickable sourceসহ
answer দেয়। Assistant generation-এর primary provider হলো Groq model
“openai/gpt-oss-120b”। Configured fallback chain-এ Hugging Face
“openai/gpt-oss-20b”, OpenRouter “nvidia/nemotron-3-nano-30b-a3b:free”,
Google Gemini “gemini-flash-latest” এবং final optional OpenAI
“gpt-4.1-mini” আছে।

সবচেয়ে গুরুত্বপূর্ণ security step হলো—vector result দেখানোর আগে approval,
ownership এবং role visibility আবার check করা হয়।

Transition:
এই search, chat ও campus workflow কোন technology layer-এর ওপর চলছে, এখন
architecture দিয়ে সেটি দেখি।


SLIDE 12 — A THREE-TIER STACK KEEPS CRH MAINTAINABLE
সময়: প্রায় ৭০–৮০ সেকেন্ড
------------------------------------------------------------
Speaker Script:

Systemটি three-tier architecture অনুসরণ করে।

Presentation tier-এ React ও Vite দিয়ে responsive single-page application
তৈরি হয়েছে। Application tier-এ Node.js ও Express REST API authentication,
business rules ও data operation পরিচালনা করে; Socket.io live communication
দেয়।

Data tier-এ MongoDB Atlas documents, ResourceChunk, embeddings এবং vector index
রাখে। Cloudinary uploaded file ও image store করে।

Signup এবং password-reset OTP Google Cloud-এর Gmail API ও OAuth 2.0-এর মাধ্যমে
পাঠানো হয়। AI service Groq-led configured fallback chain ব্যবহার করে, আর

- Local deterministic keyword safety filter

AI moderation:
- Groq text model — openai/gpt-oss-safeguard-20b
- Groq vision model — qwen/qwen3.6-27b

- OpenAI final moderation fallback — omni-moderation-latest

Fail-safe policy:
- Flagged, incomplete অথবা provider-unavailable content human review-এর জন্য
  hold হয়।
- Provider failure কখনো automatic safe verdict তৈরি করে না।

- Local ও quantized
- Bangla এবং English support
- 384-dimensional embedding
- MongoDB Atlas Vector Search primary retrieval
- In-memory cosine similarity second fallback
- Regex search final deterministic fallback

  configured ছিল; production Vercel secret faculty-কে দেখাবেন না।
- Cerebras project-এর implemented provider নয়; এটি mention করবেন না।


সম্ভাব্য Viva প্রশ্নের সংক্ষিপ্ত উত্তর
============================================================

প্রশ্ন: AI provider fail করলে কী হয়?
উত্তর: System next configured provider try করে। Moderation complete না হলে
content human review-এর জন্য hold হয়; automatic publish হয় না।

প্রশ্ন: ChatGPT ব্যবহার করেছেন?
উত্তর: ChatGPT product integrate করা হয়নি। Groq preferred provider; OpenAI API
শুধু optional final fallback।

প্রশ্ন: MiniLM কেন ব্যবহার করেছেন?
উত্তর: এটি lightweight, multilingual, locally runnable এবং 384-dimensional
embedding তৈরি করে; তাই Bangla-English semantic search-এর জন্য cost-efficient।

প্রশ্ন: RAG কী?
উত্তর: Retrieval-Augmented Generation। প্রথমে approved ও visible project data
retrieve করি, তারপর সেই context দিয়ে answer তৈরি করি এবং numbered source দিই।

প্রশ্ন: AI ভুল করলে কীভাবে control করেন?
উত্তর: Deterministic keyword filter, provider fallback, fail-safe human review,
approval state এবং role/visibility re-check—একাধিক layer ব্যবহার করি।

প্রশ্ন: Vector result কি authorization bypass করতে পারে?
উত্তর: না। Candidate retrieve করার পরে original record re-query করে approval,
ownership, department এবং role visibility check করা হয়।

প্রশ্ন: Capacity number কি guaranteed?
উত্তর: না। এগুলো report assumptions-এর planning estimate; actual load test ও
cloud quota অনুযায়ী capacity পরিবর্তিত হবে।
